## State and decisions

- `scoringPreferences.ts` supplies one request-local per-wine-type distilled-seed preference factory to single, batch, refresh and list scoring. It never generates a palate or shares user data across requests. Existing optional palate-read failure behavior is retained. Refresh no longer has its own sensory reconstruction path; the shared preference loader already supplies assembled sensory or its established manual-note fallback.
- Refresh no longer requests absent `quality_tier`. It preserves canonical location/vintage on the deployed schema and derives the assembly tier from classification. A separate legacy no-vintage fallback remains. Grapes fail explicitly before cache publication on a read error.
- `scoringEntries.ts` loads at most 50 distinct owner entry IDs in one query, then ordered grapes only for returned authorized rows. Single scoring uses the same loader. Existing canonical/wine-type fallback contracts remain. Empty requests skip work; missing IDs remain item failures.
- Batch hydration failures leave cached/direct-only items usable and return sanitized failures for dependent entry items. Entry-ID overrides now authorize/load/merge consistently with the single route, even when wine_type is supplied. This intentionally changes the former batch-only bypass; no current UI caller of the batch wrapper was found in source. Results retain order/duplicates, while bulk cache writes deduplicate IDs to avoid PostgreSQL ON CONFLICT cardinality errors. All-hit/all-terminal early exits and bulk reference prefetch remain intact.
- A scoring 503 formerly claimed the wine needed more input. Entry detail now announces temporary unavailability and offers Retry match with keyboard activation. Missing-input and low-history messages, editor workflow and Noir Refined styling remain.
- Historical reconciliation is read-only: production snapshot 921 objects, active cutoff and 487 prior verified retirements.
