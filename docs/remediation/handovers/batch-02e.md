## State and decisions
Cookie-created Supabase clients are explicitly registered for same-origin photo delivery. Server photo adapters preserve batched existence/authorization checks and missing-object nulls; internal signatures never enter these web responses. Bearer/unadopted clients keep their current response shape. `/api/photos/image` verifies cookie or bearer identity, checks the existing source-owned photo RPC on every request, and only then reads bounded bytes from the configured Storage origin. No redirects, arbitrary remote origin, active image content or cacheable success/denial. Fixed display (2048px) and original (40M decoded pixels) variants; raster re-encoding retains original dimensions for recropping. The two direct editor signing paths use the app endpoint, retaining crop-source fallback.
The guarantee covers requests begun after committed authorization changes. In-flight/retained bytes, previously issued capabilities, direct installed-client SDK requests and server-generated bearer response signatures remain outside it. No purge, key rotation, object rewrite or native release is claimed. [Supabase CDN contract](https://supabase.com/docs/guides/storage/cdn/smart-cdn).
