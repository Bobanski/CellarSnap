## State and decisions
B04a removes unauthenticated contact projections. Web login uses the existing password-sign-in API/session contract; a service client resolves the identifier and a separate anon client verifies the password. Unknown names still take a password-auth path and return a generic failure. The retired resolver returns constant 410 reload guidance. Recovery responses do not disclose looked-up contacts; only a phone supplied by the caller may be echoed. Email/username recovery uses the generic reset flow. Deliberate username/phone availability booleans remain public through limited server APIs. Six mapping/availability RPCs are executable only by service_role, with fixed empty search paths. Protected auth/availability limits require shared storage and fail closed; anonymous identity no longer depends on user-agent. Production ignores explicit local-memory mode. Old web tabs must reload. Existing mobile endpoint contracts remain supported.

B04b validates HTTP(S) URLs, credentials, ports, DNS answers and every redirect before connecting. Actual sockets pin a validated address while preserving Host/SNI/TLS verification. Non-public/mixed answers, IPv6 transition space, encoded private addresses and the Azure platform VIP are rejected. There is no production bypass or arbitrary website-script execution. One 20-second deadline spans DNS, five maximum redirects, headers and full body. Both transferred and decoded content are bounded: HTML/text 400,000 bytes, images 24 MiB, PDFs 32 MiB. Compressed responses remain supported with decompression caps. Oversized HTML reports upload guidance instead of parsing a truncated document. The final destination determines one source kind used for both limits and parsing; this fixed the uppercase `.PDF` discrepancy found in QC. Diagnostics now measure the full download and byte count. Only pinned `ipaddr.js@2.5.0` was added; no advisory upgrade campaign was mixed in.
