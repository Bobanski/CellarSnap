## State and decisions
- `POST /api/entries/[id]/details` requires a freshly authenticated bearer, with no cookie fallback even when a valid cookie is present. It bounds the streamed body to 140,000 bytes and validates allowlisted values, equal raw expected/update key sets and paired unique ordered grape arrays. The existing invoker command retains its own 65,536-byte JSON limits, owner predicate, transaction, PT409 conflict and no-op replay semantics. No service client authorizes edits.
- Only `entry_id`, `viewer_user_id` and `replayed` leave this endpoint after checking returned row identity/ownership. The RPC's full row, numeric rating and raw diagnostics are not serialized. CORS supports bearer POST/OPTIONS without credentials; responses are private/no-store. Stage-only failure logs omit payloads/tokens.
- Mobile normal and bulk-review details now require that API; no direct edit RPC or fallback. A 15-second deadline includes auth acquisition and response parsing. Owner 1–100 inputs (including nullable ordinary edits), raw snapshots, notes, explicit/untouched grapes and existing grouped-owner behavior are retained.
- QC caught delayed bulk success redirecting from Feed back to the library. Tabs retain mounted screens, so unmount-only cleanup was insufficient. Focus loss, entry/session changes and unmount now invalidate completion; the client rejects late receipts and checks generation before navigation. Aborting acceptance does not undo a committed transaction. The existing legacy queue-exit branch is guarded too, but has no current UI caller and was not browser-tested. Current Finish/Next paths publish the current entry inside the atomic command; broader queue/lifecycle semantics remain AUD-13/15.
