## State and decisions
- **B02g:** updated bearer clients explicitly negotiate `X-CellarSnap-Photo-Delivery: request-v1`; successful adopted payloads carry application image paths instead of Storage capabilities. Shared mobile PhotoImage uses fresh bearer authority, bounded no-store requests, memory data URLs, abort/timeout, foreground/session cleanup and visible Retry photo. Protected prefetch avoids persistent image caches. Configured-origin legacy URLs are converted to application paths; bearer credentials are never forwarded to arbitrary image hosts. Crop/getSize/readPhotoBytes use the original-dimension variant. Local previews and other image buckets keep existing behavior. The endpoint supports credential-free cross-origin bearer requests and never falls back from an explicit invalid bearer to ambient cookies.
- **AUD-01 remains P0/Partial:** current application requests recheck current access; retained/in-flight bytes and legacy SDK/signed/transformed URLs are outside that guarantee. Installed clients are not updated by a source merge. Old clients deliberately retain their compatibility payload; future supported-client cutover must also prevent minting new legacy capabilities. No global cache-eviction deadline is claimed.
- **B02h:** a disposable hosted label was cached as raw and transformed signed responses. Privacy changes left both readable. Copy bytes were hash-verified, synthetic references moved, and the old object deleted. Old raw/transformed URLs remained 200 at 0/5/15/30 seconds; denied at 60/90 seconds. This is one observation host, not a global SLA or proof about retained browser/native bytes. [Migration contract](../b02h-photo-revocation-contract.md) requires supported-client adoption, complete path/reference inventory, durable resumable copy/hash and conditional atomic reference swap, old-key deletion and multi-region observation. No production bulk rekey, purge, signing-key rotation or installed-client cutoff occurred.
- **B08c:** ordinary ungrouped normal/bulk-review web forms adopt the owner-only `save_entry_details` command. Only intentional changed fields participate in raw expected-state checks; untouched grapes remain untouched, explicit ordered replacement commits with details, and identical retries preserve link IDs. Stale state is a visible 409. Request deadline is 15 seconds; uncertain saves retain form input. The adopted path never falls back to the old compensation sequence. Explicit wine-type choices/clears stay authoritative during derived resolution. Supported privacy/wine-type values are validated in SQL.
- **AUD-13/15 remain Partial:** grouped edits, creates/imports, cellar decrement/clone, bulk-queue publishing and other lifecycle commands remain separate. State-convergent retries are not durable request receipts. Scoring/resolution follow-up is still best effort outside the transaction; historical grape repair and global side-effect ownership are not included. Existing direct-write clients do not inherit command serialization.
