## State and decisions
- **B02e:** cookie-created Supabase clients opt into same-origin image URLs. Existing batched signing/existence checks retain missing-image placeholders, but successful Storage signatures stay on the server. The image endpoint checks current cookie/bearer identity and `can_access_wine_photo` before reading bytes. Only configured Storage origin, no redirects, bounded transfer/time/pixels, raster re-encoding, display/original variants, no-store success and denial. The owner crop editor uses this delivery and retains original-source fallback. This repairs cookie-web delivery; bearer payloads and direct native Storage reads keep their existing compatibility behavior.
- **AUD-01 remains P0/Partial:** requests beginning after committed authorization changes are rechecked. Already authorized in-flight bytes, retained copies, historic SDK/signed/transformed URLs, CDN cache entries and installed native clients are outside this guarantee. No key rotation, bulk purge, object rewrite or global revocation deadline. [Supabase Smart CDN documentation](https://supabase.com/docs/guides/storage/cdn/smart-cdn) distinguishes token expiry from cached response eviction. Next work must define supported-client migration and measured legacy revocation.
- **B02f:** six helpers (`is_test_account`, `is_user_blocked`, `are_friends`, `can_view_test_authored_content`, `can_view_entry_standard`, `can_view_entry`) move to the private schema, retaining OIDs and ten policy dependencies. Public names become service-only invoker facades, with PUBLIC/anon/authenticated execution revoked. Private schema stays outside Data API exposure. Helper bodies and policies retain the same access semantics; source clients have no direct calls to these public helpers. Internal readers and service schema-health/share calls continue working. This closes the helper disclosure slice; AUD-06 stays Partial for native acceptance of the prior identity projection. Numeric payload privacy is still QC-01, a separate unresolved contract.
- **B08b:** owner-checked invoker `save_entry_details` locks the entry and saves allowlisted details plus optional ordered grape replacements in one transaction. Raw expected values cover exactly submitted fields; stale details or explicit grape snapshots conflict. Omitted grapes mean untouched; empty means clear; unchanged links keep IDs. If the entire requested state already exists, retry returns success without writes. This is state convergence, not a durable request-receipt system. Normal and bulk mobile editors use the typed command, retain inputs on failure, and have a 15-second deadline. No fallback to the former partial-save sequence. Intentional publishing remains. Existing direct-write clients are outside the serialized-command guarantee.
- **AUD-13/15 remain Partial:** atomic mobile details are implemented and hosted SQL is live, with native distribution pending. Web/group edits, cellar decrement/clone, creates/imports, and broader lifecycle/side-effect parity remain separate B08 slices. No historical grape repair or compensation backfill.
