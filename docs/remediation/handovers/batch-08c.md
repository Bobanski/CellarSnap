## State and decisions
- Ungrouped web normal/bulk-review detail form opts into `X-CellarSnap-Entry-Edit: atomic-v1`. It submits only touched form fields, complete pricing triples when edited, intentional publishing, and explicitly changed grapes/tasted-with selections. Expected values come from the loaded entry; omitted fields/grapes stay untouched. A missing snapshot fails before saving.
- The existing PUT handler validates and authorizes as before, then makes one `save_entry_details` call. On an adopted failure it never enters the old multi-request branch. A stale edit is 409; invalid input 400; missing command/unconfirmed result 503. Client deadline is 15 seconds and input is retained. State-convergent replay skips repeated derived work. This is not durable request receipts or guaranteed job delivery.
- Extend the command with `wine_type`, `entry_privacy`, `reaction_privacy`, `comments_privacy`; keep invoker authority, owner predicate, empty search path, row locks, signature and grants. Current UI/domain values are explicitly checked, including Friends of friends. Explicit wine-type edits/clears stay authoritative during subsequent resolution. Other derived writes/scoring refresh remain best effort outside the atomic transaction.
- Grouped forms and unadopted API callers retain their existing path. No atomic group, bulk-queue publishing, photo edits, cellar decrement/clone/create/import or historical grape-repair claim. Native runtime/distribution remains unavailable; existing mobile command behavior is regression-tested separately.

## QC discoveries and retests
- The first domain test exposed that `entry_privacy` is text and lacked a value constraint. The command now validates current domain values. `reaction_privacy` / `comments_privacy` are non-null enums, and `wine_type` is a nullable enum. The copied migration-body comment overgeneralizes those columns as text; this paragraph records the exact catalog contract without rewriting deployed SQL.
- Expanded UI review caught omitted Friends of friends in the initial command validation. The initial migration is retained immutable; a forward correction restores that existing option. The new schema test derives every current privacy/wine-type option from the web source and tests it against the actual RPC, plus invalid JSON/values. No application client had yet adopted the new fields when the correction was applied.
- Raw privacy snapshots were considered after noticing the GET display normalization. Attempts to build null/invalid interaction fixtures were rejected by the real NOT NULL/enum constraints; catalog review confirmed current valid values already match the returned values. The unnecessary API snapshot addition was removed before release; this was a harness/design assumption correction, not a new product defect.
- Initial browser locator expected an accessible Notes name. The existing label has no association; recorded QC-18 and used the real textarea name in the harness. No input markup changes in B08c.
