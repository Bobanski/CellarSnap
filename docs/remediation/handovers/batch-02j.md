## State and decisions
`scripts/storage/photo-reference-inventory.sql` enumerates all nine canonical physical path columns, every wine-photos object, shared/copied references and original siblings. It does not treat public_profiles as a writer. Maximum 10,001 rows exposes overflow; the CLI rejects >10,000 rows. CLI requires an explicit libpq target, read-only repeatable-read transaction, 30s query/35s process deadlines and 64MiB output cap. A successful snapshot is fsynced, mode 0600, atomically published without overwriting an existing file/symlink; stdout contains only aggregates and SHA256. No object mutation or deletion command exists. Repeat an interrupted inventory to obtain a new consistent snapshot; this is not a resumable rekey operation ledger.
Operator usage: `PGHOST=... PGUSER=... PGDATABASE=... CELLARSNAP_PSQL=/path/to/psql node scripts/storage/photo-reference-inventory.mjs --output /private/path/inventory.json`. Supply credentials via established libpq configuration. Do not commit snapshots: they contain raw object paths and account/reference IDs.
