## Physical-isolation release gate

Use an owner-only rating relation (entry/account FKs, constrained nullable 1–100 value, RLS and reviewed service access), or an equivalently proven owner-only contract. Decide migration design with complete transaction and snapshot tests before implementation. Keeping readable legacy numbers while adding a private table is not containment. Removing old numbers/column privileges immediately would break current direct owner reads/writes and old installed clients.

Required order: finish supported API readers; inventory/replace native create/library/edit and operator writes; define minimum supported client plus delivery/adoption evidence; implement atomic source transfer and updated knowledge/scoring commands in a disposable replay; verify owner/friend/FOF/stranger/block/test/anon REST, RPC, API and realtime access (including filters/order/embedded joins); then explicitly coordinate backfill, authority cutoff and live verification. No migration or physical cutoff is authorized by this inventory alone. Recheck external consumers and installed releases; source search cannot prove their absence.
