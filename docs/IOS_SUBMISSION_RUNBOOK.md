# iOS submission runbook

Updated September 26, 2026. Start with [current launch gates](remediation/ios-launch-readiness.md), the [submission packet](APP_STORE_SUBMISSION_PACKET.md), and the latest [remediation handover](remediation/README.md). This replaces the older March instructions. Connected tools can perform preparation and verification; the account owner completes interactive Apple authentication, agreements and any missing account configuration.

1. **Reconcile the exact candidate.** #167/#168/#165 are merged on main; `fix/ios-submission-readiness` upgrades the native candidate to Expo SDK 57, adds release contracts/privacy-manifest generation and removes unused sensitive permissions. Merge/release state must be rechecked before building. Deploy the matching backend and privacy UI before distributing the mobile candidate. Do not submit the older internal build 2.
2. **Apple prerequisites.** Cluster must ship from the Cluster Wine, LLC organization team, not the inspected personal `Individual` team. The Account Holder accepts agreements and invites `eitan@clusterwine.app` as Admin with Certificates, Identifiers & Profiles access. Because no build was uploaded, inspect the personal-team `com.cellarsnap.mobile` Sign in with Apple grouping, safely release that unused identifier, and recreate it on the company team. Create the company App Store Connect record and protected API key only after that ownership is verified. Verify the Supabase Apple provider/audience and `cluster://auth/callback`; do not invent IDs or commit keys.
3. **Complete company signing.** In `apps/mobile`, run `eas credentials --platform ios` only after the company invitation is active, select the Cluster Wine, LLC team, and finish Apple authentication/2FA. Do not paste passwords/codes into chat. The personal-team credential inspection was exited unchanged; no store IPA was produced. Record the team and signing outcome without secrets.
4. **Verify production environment.** EAS production must resolve `EXPO_PUBLIC_WEB_API_BASE_URL=https://cellarsnap.app` and the intended Supabase URL/public key/auth mode. Exclude temporary local env overrides. Inspect the resolved build configuration and final binary's requests. Never ship a loopback/LAN QC host or service-role key.
5. **Build for the store.** Production profile uses store distribution and an explicit matching SDK 57 prebuild template. Verify the actual Xcode/iOS SDK image meets current Apple requirements, generated Apple Sign In entitlement and merged privacy manifest. Confirm microphone/Face ID/audio-recording permissions remain absent unless the product actually adopts those features. Export/prebuild are not native compile or device acceptance. Check `app.json` for current version/build number and choose an unused build number if a prior upload already used it.
6. **Install and test.** Record iPhone model/iOS/version/build. Exercise Apple first/repeat/cancel login, password login/recovery, session restore; consent decline/manual logging, allow/AI and revoke; camera/library denial and recovery, scan/crop; create/edit/private photos and ratings; social report/block; sign-out and deletion with a disposable review fixture account. Capture screenshots from this exact binary. Browser Expo evidence is only fallback coverage.
7. **Prepare the listing.** Use the field-length-checked [submission packet](APP_STORE_SUBMISSION_PACKET.md). Obtain owner sign-off on name/category/artwork/copy, publish the current company privacy/terms pages, and capture screenshots from the exact accepted binary. Reconcile the source-grounded [App Privacy draft](APP_PRIVACY_LABELS.md) with actual provider retention/logging settings. Complete Apple's current age-rating questionnaire, including alcohol/UGC/social communication and any higher override required by the app's age terms; “always 17+” is obsolete guidance. Resolve QC-25 filtering and moderation-response ownership before review.
8. **Reviewer access.** Provide a dedicated working review account, synthetic populated fixtures and navigation notes in App Store Connect. Do not expose internal tester credentials or private users' content. Confirm reporting/support ownership and that reviewer access includes the relevant features.
9. **Upload the exact store build.** Resolve the App Store Connect numeric app ID and team from the real account; do not invent identifiers. Configure submission through the authenticated account or protected EAS/CI secrets. Confirm `eas submit:status` can resolve the bundle before relying on non-interactive upload. Use the verified EAS build ID, not `--latest`.
10. **Submit for review separately.** Wait for processing, select the exact build, finish metadata/privacy/export-compliance/review information and choose release timing. Uploading with EAS only delivers to App Store Connect/TestFlight; record the actual App Review status/receipt before calling it submitted.

```sh
# apps/mobile; after signing, final code/backend and production env are ready
eas build --platform ios --profile production --non-interactive
eas submit --platform ios --profile production --id <verified-store-build-id>
```

Sources: [Expo iOS submission](https://docs.expo.dev/submit/ios/), [Apple submission](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/submit-an-app/), [Apple age ratings](https://developer.apple.com/help/app-store-connect/manage-app-information/set-an-app-age-rating/). Keep build, installation, upload and review states distinct.
